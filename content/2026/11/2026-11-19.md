## ① AI / LLM / Agents / Developer Tools

### 1. GitHub Copilot 新增 Gemini 4 Neon
**摘要｜** GitHub 11/18 宣布 Gemini 4 Neon 正式提供給符合資格的 Copilot 方案，採使用量計費並逐步開放。

**為什麼重要｜** 開發者可在多個 IDE 與 CLI 選擇新的 Agent 程式碼模型。

**二階影響｜** 企業可能依延遲、每項任務成本與修改範圍建立模型路由。

**我的判讀｜** Google 所稱較低成本與較少非必要修改屬廠商比較，仍需獨立測試。

**來源｜** [GitHub，11/18](https://github.blog/changelog/2026-11-18-gemini-4-neon-in-github-copilot/)

### 2. Copilot 擴增八種 MCP 連接服務
**摘要｜** GitHub 11/18 開放預覽 Box、Supabase、Buildkite、Calendly、ClickUp、Mixpanel、Webflow、Wix 等連接服務。

**為什麼重要｜** Agent 可在同一工作階段跨程式碼、資料庫與專案工具操作。

**二階影響｜** 權限最小化、操作稽核及第三方資料邊界將更重要。

**我的判讀｜** 企業仍需管理員允許預覽功能及 MCP 白名單，不是所有使用者自動開通。

**來源｜** [GitHub，11/18](https://github.blog/changelog/2026-11-18-connect-supabase-box-calendly-and-more-to-copilot/)

### 3. Copilot 團隊共用 Agent Plugins 正式提供
**摘要｜** GitHub 11/18 宣布組織團隊可設定預設 Agent Plugins，支援 VS Code、Copilot app 與 CLI。

**為什麼重要｜** 團隊不必讓每位開發者重複安裝相同工具。

**二階影響｜** 團隊層級的標準化有利於減少環境差異，也可能擴大權限誤設的影響。

**我的判讀｜** 企業與組織政策仍優先於團隊設定，子團隊也不會自動繼承。

**來源｜** [GitHub，11/18](https://github.blog/changelog/2026-11-18-customize-github-copilot-for-your-team/)

### 4. GitHub Team 自動執行安全風險評估
**摘要｜** GitHub 11/18 宣布 GitHub Team 組織自動執行免費安全風險評估，供管理員檢視機密憑證與程式碼弱點。

**為什麼重要｜** 降低初次安全盤點的操作門檻。

**二階影響｜** 組織可把發現結果接入弱點修復與責任分派流程。

**我的判讀｜** 自動風險評估不是持續修復保證，仍須人工判定優先順序。

**來源｜** [GitHub，11/18](https://github.blog/changelog/2026-11-18-security-risk-assessments-run-automatically-on-github-team/)

### 5. GitHub Event Streams 提供事件驅動 Agent 預覽
**摘要｜** GitHub 11/17 發表 Event Streams 預覽，讓 Agent 與自動化程式接收即時事件而非持續輪詢。

**為什麼重要｜** Agent 工作流程可以更接近事件驅動架構。

**二階影響｜** 可能減少無效輪詢與延遲，但需設計重送、去重及權限檢查。

**我的判讀｜** 預覽功能仍應評估可靠性與營運限制，不宜直接假設可取代所有 webhook。

**來源｜** [GitHub，11/17（背景）](https://github.blog/changelog/2026-11-17-github-event-streams-is-now-in-preview/)
