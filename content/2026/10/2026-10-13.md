## ① AI / LLM / Agents / Developer Tools
### 1. Meta Muse Wonder / Wonder Full
**摘要｜** 原稿記錄10/12發布，Wonder提供API与Muse Code、Full限訂閱者，US$4 input/US$20 output per1M，官方與Astra、Fable比較，Active Memory/Focus維持長期資訊。

**為什麼重要｜** 差異不只在單次回答，也在跨天或月的任務狀態。

**二階影響｜** Persistent agents需要記憶更新、遺忘、權限與多任務一致性。

**我的判讀｜** 看long-horizon success、memory accuracy、cost/task；搜尋歷史不等於正確理解目前事實。

### 2. 英國AI Security Institute測試權
**摘要｜** 原稿記錄部長確認可測Argon等frontier models，與美方及供應商合作，屬自願安排，不是全部模型同等審查。

**為什麼重要｜** 第三方可檢查內部測試未涵蓋的風險。

**二階影響｜** Pre-release、controlled rollout、monitoring、incident review可能標準化。

**我的判讀｜** 模型能力與接tool/credential後的system risk分開測，API安全分數不等於企業部署安全。

### 3. SPUR與内容使用標準
**摘要｜** 原稿記錄NYT、AFP、Economist加入，逾80成員、20多國，推content telemetry及授權付費，背景為搜尋流量下降。

**為什麼重要｜** RAG與research依賴內容，但收益未必回流供應者。

**二階影響｜** Source、license、retrieval、model usage、attribution可能需連續追蹤。

**我的判讀｜** Data provenance應含授權期限與用途；引用來源不等於取得訓練或再散布權利。

### 4. GitHub push attribution
**摘要｜** 原稿列Enterprise limited preview，在author、committer之外保留已認證pusher，新增committer must match pusher規則。

**為什麼重要｜** Git metadata可自行指定，不完全等於實際推送身份。

**二階影響｜** 多Agent需要identity、worktree、commit、PR、CI、approval完整鏈。

**我的判讀｜** Pusher不等於撰寫者；共用token仍無法區分agents。需獨立服務身份及來源紀錄。

### 5. JetBrains Copilot與MCP生命週期
**摘要｜** 原稿記錄管理預設模型、IDE diagnostics直接修復、MCP auto-start控制，停止2025.1、最低2025.2。

**為什麼重要｜** MCP可能帶來執行權及資源消耗，不只是context。

**二階影響｜** 工具啟動、credentials、session及permissions需治理。

**我的判讀｜** 依任務需要最小授權與啟動，而非預設暴露全部工具；版本支持應回官方核對。

## ② Technology Products / Hardware / Networking
### 1. Maia 300 rack-scale inference
**摘要｜** 原稿列TSMC N2P、每顆8組HBM4、18TB/s、950W；每rack96顆、27.6TB、1.7PB/s、167kW，2027部署，宣稱比領先GPU每MW多40%tokens、較Maia200 rack最高七倍。

**為什麼重要｜** KPI由單芯片FLOPS轉向整體tokens/W與tokens/$。

**二階影響｜** Memory、network、cooling與serving stack共同決定ASIC競爭力。

**我的判讀｜** 看真實模型、精度、context、batch與SLA，特別TTFT、decode、KV利用率，不把不同測試的倍率直接比較。

### 2. AMD Helion：CPU agent workers
**摘要｜** 原稿列OCP blueprint不同於Helios，CPU-only最多32,768 EPYC cores，混合EPYC與MI350P，token router選不同models，11月配置。

**為什麼重要｜** Browser、shell、tests、文件與orchestration主要需要CPU，不是每個Agent一張GPU。

**二階影響｜** CPU workers可彈性擴展，GPU inference pools集中共享。

**我的判讀｜** Kubernetes多Agent應分配CPU/IO與推論資源，還需timeout、worktree隔離及memory/latency budget。

### 3. NVIDIA開放rack與管理元件
**摘要｜** 原稿記錄Vera Rubin部分reference design與DSX components，包含Config Manager、Cluster Readiness Engine、Rack Management Service、Cluster API Provider。

**為什麼重要｜** 管理、驗證、provisioning與硬體健康是AI factory運作核心。

**二階影響｜** Bare metal、network及K8s可更標準化整合。

**我的判讀｜** 開放reference不等於開放GPU全部IP。Pre-job stress與topology驗證可避免長工作中途失敗，但也需可靠的錯誤判斷。

### 4. NVIDIA × Cisco USFP
**摘要｜** 原稿列400Gb/s per lane、最高12.8Tb/s module、最高四倍密度與1.3倍能效，Amphenol及TE參與，屬規格目標。

**為什麼重要｜** Front-panel密度、模組功耗與網路層數限制大cluster。

**二階影響｜** Optical、connector、laser、DSP及switch thermal一起演進。

**我的判讀｜** 需BER、散熱、維修與reliability驗證，不以理論模組容量推定整個資料中心效能。

### 5. AMD Ryzen AI Halo
**摘要｜** 原稿列Max+ PRO495、192GB unified memory、Zen5、Radeon，面向local agents與多模態，展示特定量化下大型模型可容納。

**為什麼重要｜** 權重與KV常是本地部署第一個限制。

**二階影響｜** 容量、x86、ROCm與CUDA各有取捨。

**我的判讀｜** 放得下不等於足以多人低延遲服務；要看bandwidth、kernels、TTFT、batch及每瓦吞吐。
