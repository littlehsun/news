## ① AI / LLM / Agents / Developer Tools

### 1. Anthropic 發布 Claude Haiku 5.5，強化低成本工作模型

**摘要｜** Anthropic 10/7 推出 Claude Haiku 5.5，強調快速與較低單位 Token 成本，適用摘要、分類、簡單工具呼叫及大量 Subagent 任務。效能與節省幅度為廠商公布結果。

**為什麼重要｜** 大型 Agent Workflow 需要大量非高難度工作，真正的經濟性取決於是否能將不同子任務交給合適模型。

**二階影響｜** 企業可能採用高能力 Planner 搭配低成本 Worker 與獨立 Verifier 的架構，減少推論資源消耗。

**我的判讀｜** 比較模型應測量 Tool Calling 成功率、重試成本及每個完成任務的總花費，而非只看 Input Token 價格。

**來源｜** [Anthropic 官方產品資訊（2026/10/07）](https://www.anthropic.com/claude-haiku-5-5)

### 2. GitHub Copilot Local Sandboxing 正式 GA

**摘要｜** GitHub 10/7 宣布，Copilot CLI、Copilot App 與支援 Agent Host 的 VS Code Sessions 已正式提供 Local Sandboxing。Microsoft eXecution Container（MXC）將共用政策轉成不同作業系統的原生限制。

**為什麼重要｜** Agent 可以直接執行命令，僅靠 Prompt 或人工提醒不足以限制檔案、網路及憑證存取。

**二階影響｜** 企業可將 Agent 工具權限納入集中政策管理，設定可讀寫目錄、網路連線與 Git 認證邊界。

**我的判讀｜** 應測試規避路徑與稽核能力；Sandbox 限制的是工具執行，不代表模型本身的輸出已全部安全。

**來源｜** [GitHub Changelog（2026/10/07）](https://github.blog/changelog/2026-10-07-local-sandboxing-for-github-copilot-now-generally-available/)

### 3. Copilot CLI 可從 Ollama 探索本地模型

**摘要｜** GitHub 10/7 宣布 Copilot CLI 自 1.0.94-0 起可在 /model 選單探索執行中的 Ollama 模型，選擇 Provider 與 Endpoint 後加入目前 Session；模型須支援 Tool Calling 與 Streaming。

**為什麼重要｜** 讓 Coding Agent 使用自架推論變得更容易，為企業內網與混合模型策略提供更多選擇。

**二階影響｜** Copilot CLI 可能同時管理雲端和本地模型，但必須仔細設定隱私、路由及 GitHub Telemetry。

**我的判讀｜** GitHub 特別指出：選用 Ollama 不會自動啟用離線模式；COPILOT_OFFLINE=true 也不代表遠端模型端點不會接收內容。

**來源｜** [GitHub Changelog（2026/10/07）](https://github.blog/changelog/2026-10-07-discover-local-models-in-github-copilot-cli/)

### 4. Google Playground 以自然語言建立可互動遊戲

**摘要｜** Google 10/7 公布 Playground 實驗平台，結合 Gemini 等生成式模型，讓使用者以描述方式建立、測試及分享小型可互動遊戲，並與 Unity 推進相關製作工具探索。

**為什麼重要｜** AI 產出開始從文字與靜態圖片移向具有狀態、規則與互動邏輯的軟體作品。

**二階影響｜** 未來原型設計、遊戲教學及互動式媒體製作流程可能縮短，但版本維護與程式品質仍需工具支援。

**我的判讀｜** 能生成一次可玩的畫面不代表持續修改後仍可靠；應觀察遊戲規則一致性、測試覆蓋與可編輯性。

**來源｜** [Google 官方部落格（2026/10/07）](https://blog.google/innovation-and-ai/technology/ai/playground-experimental-gaming-platform/)

### 5. GitHub 推出針對憑證外洩的專用 AI 偵測模型

**摘要｜** GitHub 10/7 公布新型 Secret Detection Model，可利用前後程式碼判斷疑似密碼，即使其沒有固定 Token 格式。Password Alerts 已升級；Push Protection 與部分安全指令仍在預覽或規劃階段。

**為什麼重要｜** AI 生成的程式碼也可能意外包含機密；傳統只靠 Regex 的掃描較難辨識任意格式的 Password。

**二階影響｜** 企業安全流程可結合 GitHub Secret Scanning、PR Review 和 CI，降低金鑰意外進入 Repository 的機會。

**我的判讀｜** 預覽功能不應寫成全部 GA；仍須測試 False Positive、真正憑證偵測率與機密撤銷作業。

**來源｜** [GitHub Changelog（2026/10/07）](https://github.blog/changelog/2026-10-07-purpose-built-model-for-leaked-secret-detection/)
