### 2. Copilot Local Sandboxing 正式供應，以作業系統限制工具權限
**摘要｜** GitHub 10/7 宣布本地沙箱在 Copilot CLI、Copilot App 與使用 Agent Host 的 VS Code 工作階段正式供應。MXC 將政策轉成 Windows、macOS、Linux 的原生限制，涵蓋檔案、網路與部分憑證使用；企業可強制套用政策。

**為什麼重要｜** 沙箱提供模型之外的執行邊界。即使模型誤判指令，工具也不應自動取得整台電腦及所有網路的權限。

**二階影響｜** 企業可能把程式開發 Agent 納入端點及身分治理，並要求保留操作紀錄、例外授權與政策變更歷史。

**我的判讀｜** 正式供應不代表每種設定都自動安全。仍要確認沙箱是否啟用、哪些工具被涵蓋，以及允許路徑與網路範圍；不能把提示詞限制當成相同的安全保證。

**來源｜** [GitHub：Copilot 本地沙箱正式供應（2026-10-07）](https://github.blog/changelog/2026-10-07-local-sandboxing-for-gitHub-copilot-now-generally-available/)

### 3. Copilot CLI 可探索 Ollama 模型，但本地推論不等於離線模式
**摘要｜** GitHub 10/7 公告，Copilot CLI 1.0.94-0 起可透過 `/model` 探索正在執行的 Ollama 模型。使用者須先備妥模型，並確認端點；模型需要支援工具呼叫與串流。選擇本地模型不會自動啟用 `COPILOT_OFFLINE=true`。

**為什麼重要｜** 這讓開發工具可使用自管模型，但同時要求清楚區分模型請求、工具網路與其他服務連線的資料流向。

**二階影響｜** 企業可能在同一開發介面內，依資料敏感度切換本地及雲端模型；也需要逐一確認工具、遙測與外部整合的行為。

**我的判讀｜** 我會驗證端點實際位置、網路紀錄與工具相容性。即使開啟離線模式，若模型端點仍指向遠端，提示內容仍可能送到該端點，不能靠功能名稱推論資料不外流。

**來源｜** [GitHub：探索 Copilot CLI 本地模型（2026-10-07）](https://github.blog/changelog/2026-10-07-discover-local-models-in-github-copilot-cli/)
